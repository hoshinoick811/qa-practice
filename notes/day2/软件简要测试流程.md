# 软件测试流程

## 一、需求分析
### 目的：
1. 确定各部门对需求理解一致
2. 站在不同角度对需求做查漏补缺

## 二、计划编写
### 核心：
1. 测试目标
2. 测试人员、进度安排
3. 测试策略

## 三、用例设计
- 设计测试的文档
### **考虑点：** 质量模型（功能、性能、兼容性、易用性、安全性）
### **作用：**
- 防止漏测
- 实施测试的标准
### **用例编写格式：**
- 用例编号：项目+模块+编号
- 用例标题：预期结果+操作步骤
- 模块/项目：所属项目或者模块
- 前置条件：要执行此条测试用例需要哪些前置操作
- 优先级：表示测试用例的重要程度或者影响力（P0-P4，P0为最高）
- 测试步骤：操作的数据（没有可为空）
- 预期结果：期望获取的结果
### **用例编写示例**

 | 用例编号 | 用例标题 | 项目/模块 | 前置条件 | 优先级 | 测试步骤 | 测试数据 | 预期结果 | 实际结果 |
 |----------|---------|----------|---------|--------|---------|---------|---|---|
 | login_001 | 合格（8位数字） |  |  | P0 |  | 12345678 | 合格 |
 | login_002 | 不合格（4位数字） | 登录 | 打开软件 | P0 | 1.输入用户名<br>2.点击验证 | 1234 | 不合格 |
 | login_003 | 不合格（8位非数字） |  |  | P0 |  | a1234567 | 不合格 |



## 四、用例执行
- 执行测试的文档

## 五、缺陷管理
- 提交->验证->关闭

## 六、测试报告
- 测试目标、测试过程、缺陷统计、缺陷分析、测试总结
